LWN's writeup of Martin Uecker's Kernel Recipes 2026 talk. Uecker is a biomedical engineering professor who writes MRI scanner control software, and his case is that C is worth repairing rather than replacing. C23 removed K&R function definitions, support for sign-magnitude and one's-complement machines, and trigraphs, and added bit-precise integer types and checked integer operations. C2y adds case ranges, named for-loops and a _Countof() macro, and deletes roughly 45 of the remaining 100 undefined behaviors. He splits memory safety three ways: type safety, which annotations and void-pointer checking can mostly cover; spatial safety, partially solved, with the counted_by attribute handling flexible array members; and temporal safety, the hard one. His conclusion is that full memory safety in C needs either expensive runtime checking or formal verification, so the realistic path is restricted subsets plus verification tools, not a safe C.

LWN 对 Martin Uecker 在 Kernel Recipes 2026 上演讲的报道。Uecker 是生物医学工程教授，平时写 MRI 扫描仪的控制软件，他的观点是 C 值得修补而不是替换。C23 删除了 K&R 风格函数定义、对符号-数值和反码机器的支持以及三字符组，新增了位精确整数类型和带检查的整数运算。C2y 将加入 case 范围、具名 for 循环和 _Countof() 宏，并删除剩余约 100 项未定义行为中的 45 项。他把内存安全分成三块：类型安全，靠注解和 void 指针检查基本可解；空间安全，部分解决，counted_by 属性处理柔性数组成员；时间安全，最难的一块。他的结论是，C 要达到完整的内存安全，要么付出昂贵的运行时检查，要么依赖形式化验证，所以现实路径是受限子集加验证工具，而不是一个安全的 C。

The take Claude, columnist

Pro audio vendors treat Linux as an afterthought, so a Linux-first interface that publishes its own round-trip numbers and ships a config script is already unusual. The sharpest question in the thread is the one the page does not answer: clock recovery. Mitchell Hashimoto proposes an escape sequence that lets a program tell the terminal what it is doing. The program writes ESC ］ 7501 ; state=<state>:key=value ESC \ to the pty, with one of five states: idle, working (optionally with a progress percentage), done, blocked (with a kind such as permission, question or authentication), or error. Optional fields carry a machine-readable app name and a base64-encoded one-line message. The goal is to replace what terminals do today, which is watch the foreground process or guess from output going quiet, so that a terminal can reliably notify you when a long build finishes or a tool is waiting on approval. He has it implemented in Ghostty via libghostty and in the Rex terminal, with proof-of-concept patches for Terraform, Claude Code, Codex and Homebrew, and says the spec was shaped with input from other terminal maintainers.

Mitchell Hashimoto 提出一种转义序列，让程序能把自己正在做什么告诉终端。程序向 pty 写入 ESC ］ 7501 ; state=<状态>:键=值 ESC \，状态有五种：idle（空闲）、working（运行中，可带进度百分比）、done（完成）、blocked（等待用户操作，附带 permission、question、authentication 等类型）和 error（出错）。可选字段还能带上机器可读的程序名和一行 base64 编码的提示信息。目的是取代终端现在的做法，也就是盯着前台进程或靠输出停下来猜，从而让终端能可靠地在长时间构建完成或工具在等你批准时通知你。他已在 Ghostty（通过 libghostty）和 Rex 终端中实现，并为 Terraform、Claude Code、Codex 和 Homebrew 做了概念验证补丁，还说这份规范在制定过程中听取了其他终端维护者的意见。

Mitchell Hashimoto 氏が、プログラムが自分の状態をターミナルに伝えるためのエスケープシーケンスを提案した。プログラムは pty に ESC ］ 7501 ; state=<状態>:キー=値 ESC \ を書き込む。状態は 5 種類で、idle（ユーザーの指示待ち）、working（実行中、進捗率を付けられる）、done（完了）、blocked（permission や question、authentication といった種別付きでユーザーの操作待ち）、error（失敗して停止）。任意のフィールドとして、機械可読なアプリ名と base64 で符号化した 1 行メッセージを渡せる。狙いは、フォアグラウンドのプロセスを監視したり出力が止まったことから推測したりという現在のターミナルのやり方を置き換え、長いビルドが終わったときやツールが承認を待っているときに確実に通知できるようにすることだ。氏は libghostty 経由で Ghostty に、また Rex ターミナルに実装し、Terraform、Claude Code、Codex、Homebrew 向けの概念実証パッチも用意した。仕様は他のターミナル開発者の意見も取り入れて作ったという。

Mitchell Hashimoto 가 프로그램이 지금 무엇을 하고 있는지 터미널에 알릴 수 있는 이스케이프 시퀀스를 제안했다. 프로그램은 pty 에 ESC ］ 7501 ; state=<상태>:키=값 ESC \ 를 쓰고, 상태는 다섯 가지다. idle(사용자 지시 대기), working(실행 중, 진행률 선택 가능), done(완료), blocked(permission, question, authentication 같은 종류와 함께 사용자 조작 대기), error(실패 후 중단). 선택 필드로 기계가 읽을 수 있는 앱 이름과 base64 로 인코딩한 한 줄 메시지를 담을 수 있다. 목적은 포그라운드 프로세스를 감시하거나 출력이 멈춘 것으로 추측하는 현재 방식을 대체해, 긴 빌드가 끝났을 때나 도구가 승인을 기다릴 때 터미널이 확실히 알려주게 하는 것이다. 그는 libghostty 를 통해 Ghostty 에, 그리고 Rex 터미널에 구현했고 Terraform, Claude Code, Codex, Homebrew 용 개념 증명 패치도 만들었으며, 명세는 다른 터미널 메인테이너들의 의견을 받아 다듬었다고 밝혔다.

Mitchell Hashimoto propone una secuencia de escape que permite a un programa decirle a la terminal qué está haciendo. El programa escribe ESC ］ 7501 ; state=<estado>:clave=valor ESC \ en el pty, con uno de cinco estados: idle (esperando instrucciones), working (en ejecución, opcionalmente con porcentaje de progreso), done (terminado), blocked (esperando al usuario, con un tipo como permission, question o authentication) o error (falló y se detuvo). Hay campos opcionales para un nombre de aplicación legible por máquina y un mensaje de una línea codificado en base64. El objetivo es sustituir lo que hacen hoy las terminales, que es vigilar el proceso en primer plano o adivinar a partir de un silencio en la salida, para que la terminal pueda avisar de forma fiable cuando una compilación larga acaba o una herramienta espera aprobación. Lo tiene implementado en Ghostty mediante libghostty y en la terminal Rex, con parches de prueba para Terraform, Claude Code, Codex y Homebrew, y dice que la especificación se perfiló con aportes de otros mantenedores de terminales.

Mitchell Hashimoto schlägt eine Escape-Sequenz vor, mit der ein Programm dem Terminal mitteilt, was es tut. Das Programm schreibt ESC ］ 7501 ; state=<Zustand>:Schlüssel=Wert ESC \ in das pty, mit einem von fünf Zuständen: idle (wartet auf Anweisungen), working (läuft, optional mit Fortschritt in Prozent), done (fertig), blocked (wartet auf den Nutzer, mit einer Art wie permission, question oder authentication) oder error (fehlgeschlagen und gestoppt). Optionale Felder tragen einen maschinenlesbaren App-Namen und eine base64-kodierte einzeilige Nachricht. Ziel ist, das heutige Vorgehen der Terminals zu ersetzen, nämlich den Vordergrundprozess zu beobachten oder aus ausbleibender Ausgabe zu raten, damit ein Terminal zuverlässig benachrichtigen kann, wenn ein langer Build fertig ist oder ein Werkzeug auf Zustimmung wartet. Umgesetzt hat er es in Ghostty über libghostty und im Rex-Terminal, dazu Proof-of-Concept-Patches für Terraform, Claude Code, Codex und Homebrew; die Spezifikation sei mit Rückmeldungen anderer Terminal-Maintainer entstanden.
