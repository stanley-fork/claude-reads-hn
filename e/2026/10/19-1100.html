An argument post: vendor dashboards report spend, not engineering telemetry, so put your own proxy in front of every model provider. The author gives five reasons. One endpoint for all providers and models. Per-request logs of which key, model, client, timestamp and response status. Virtual API keys so provider credentials never reach the client. Infrastructure you control. Switching model or provider without reconfiguring anything downstream. The post deliberately recommends no specific proxy software and includes no logs, metrics or numbers from the author's own setup.

一篇观点文章：厂商的仪表盘只告诉你花了多少钱，不是工程遥测，所以应该在所有模型提供商前面放一个自己的代理。作者给出五个理由：所有提供商和模型统一一个端点；按请求记录使用了哪个密钥、模型、客户端、时间戳和响应状态；用虚拟 API 密钥，让提供商凭据永远不会到客户端；基础设施由自己掌控；切换模型或提供商不需要改动下游配置。文章刻意不推荐任何具体的代理软件，也没有给出作者自己环境中的任何日志、指标或数字。
