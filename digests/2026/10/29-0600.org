** Qwenputer: A functioning, deterministic RISC-V CPU inside Qwen3.5 :llm:risc-v:qwen:architecture:emulation:
:PROPERTIES:
:ID:       50282838
:URL:      https://divagr.com/blog/qwenputer

*** TLDR
Divyansh Agrawal compiled a 32-bit RV32IM RISC-V CPU into 11 extra layers of a stock Qwen 3.5 4B. The trick is Gated DeltaNet: set the gate and write strength to 1 and use one-hot key encoding, and a GDN head becomes exact addressable RAM whose state stays the same size no matter how long the conversation runs, unlike a KV cache. Instructions arrive as token sequences, attention heads do lookups, feed-forward units do arithmetic. It passes the official RISC-V test suites, ran 18 million instructions without an error, runs C and MicroPython inside the forward pass, and lifts accuracy on DeepMind arithmetic benchmarks from 72.5-95% to 97.5-100%. There is also an in-weight filesystem holding up to 512 files, around 53,000 tokens, at 90% retrieval accuracy. The bill: an 18.8 GB checkpoint, 24 GB of GPU memory, and about 3,200 CPU tokens per second on an L4.

*** Take
The interesting result is not the CPU, it is that DeltaNet's fixed-size state can be driven as exact memory at all. The CPU is an expensive way to prove it. Doubling the checkpoint to get a 3,200-instruction-per-second core, where each instruction costs several decoded tokens, is a worse deal than the tool call it replaces, and andai says so in the thread. Read it for the memory mechanism, not for the arithmetic.

*** TLDR
A gist from flamerix-ai exports Claude Code's OpenTelemetry data and groups claude_code.api_request events by query_source. The agent-summary feature, which asks a model roughly every 30 seconds to 'describe your most recent action in 3-5 words' for the panel status line, came out at 16.4% of Claude Code spend, against 15.7% for the main conversation, and 19.7% of all API requests. 96% of that spend was on Opus, at an input-to-output ratio near 9,000:1, and the output never reaches the conversation. Turning summaries off took both numbers to zero. The author notes that on subscription plans the real loss is rate-limit headroom rather than invoice, and cites independent measurements in the 18-26% range.

*** Take
9,000 tokens in for five words out, every 30 seconds, is the kind of waste nobody finds until someone exports telemetry. But the headline number is softer than it reads: jakozaur measured about 8% and says it only affects subagents, and HeavenFox is right that most of those input tokens are cache reads, so the dollar figure is not what the percentage implies. The cost that is real is rate-limit headroom, which on a subscription plan is the only budget you have. The fix is a config flag, and the question worth asking is why the default sends this to Opus.
