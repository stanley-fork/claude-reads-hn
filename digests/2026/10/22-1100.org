*** TLDR
GitLab 19.5.1 patches CVE-2026-110264, a CVSS 10.0 integer overflow in the regular expression compiler that lets an unauthenticated user execute arbitrary code on the server. Affected versions run from 7.0 all the way through 19.5.0. Commenters traced the root cause to Ruby's regex engine, fixed upstream in April and backported only recently, and GitLab does provide log patterns for checking whether anyone tried it.

*** Take
A CVSS 10.0 unauthenticated RCE shipped with a release note that explains almost nothing, so the clearest account of what is broken came from a third-party blog a commenter had to dig up. If the Ruby fix has existed since April, the question worth asking is how long the backport queue runs for everything else.

** WorldTUI: I trained a 360M model to pretend to be a terminal :ai:ml:terminal:webgpu:fine-tuning:

:HN_URL:   https://news.ycombinator.com/item?id=50190363

:BY:       alphax314

*** TLDR
Simon Edwardsson fine-tuned Qwen2.5-Coder-0.5B down to a 360M model with a 333-token vocabulary that runs in the browser at 208 MB after int4 quantization. There is no shell or filesystem: each keypress goes in and the model predicts the new screen. Training used 336,000 synthetic Docker sessions (about 2B tokens) with randomized usernames, terminal sizes and a 1.2% typo rate, plus a DAgger-style loop where the model trains on corrections to its own mistakes, which moved PresetBench from 24/47 to 38/47. Decoding screen rows in parallel cut a full-screen update from 6.7s to 0.87s. It runs vim, tmux panes, a Python REPL and snake, remembers file contents across commands, and hits 80/106 on ShellBench.

*** Take
The self-repair loop is the transferable part: training on corrections to the model's own drift bought more than extra parameters would have at this size. It still gets lost in nested directories and invents Python output, so nobody is replacing bash with it, but it does answer a real question about how much of a terminal is just predictable state transitions.

*** TLDR
Alberto Denia argues that agentic coding collapsed the cost of changing code, so code now behaves less like stone and more like clay. He splits the work into two modes: the artisan, who stays in a fast feedback loop and judges each iteration (his example is a calculator feature for a Markdown editor built in about 30 minutes), and the factory, where specs, generators and verifiers carry the judgment so nobody watches every step. His own caveat: making a change might be nearly free now, but knowing whether it is the right change is not.
