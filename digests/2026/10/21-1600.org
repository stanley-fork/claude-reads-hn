*** TLDR
PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35 fix two unauthenticated remote code execution bugs. CVE-2026-109618 is memory corruption: hitting PHP's memory limit at the wrong moment leaves partially initialized data that later gets treated as valid. CVE-2026-109619 leaves internal state pointing at memory freed by an earlier request, and the Foundation says that use-after-free was confirmed as working RCE against real applications on Apache with mod_php under default settings. The release moved up a day because CVE IDs with wrong details circulated on October 20, pushing the pre-announcement to 19:30 UTC that evening. After the leak, Calif, one of the firms that reported the bugs, published a video demonstrating exploits against targets; deleted copies spread anyway. Chainguard separately shipped patched container images before disclosure, letting attackers diff the fix while everyone else waited. The Foundation's answer: an Ecosystem Security Team created in May 2026, Alexandre Daubois on triage and fixes, Daniel Scherzer on hardening, sanitizer builds and CI-matched reproduction environments, and majority instead of consensus for security decisions.

*** Take
The post is two documents stapled together: a competent incident writeup and a funding pitch. The pitch earns its place. Inside one 24-hour window, two reporting firms and a container vendor each broke coordination, and the Foundation's remedy is to hire more engineers who know the codebase. That is the real finding. PHP serves a large share of the web on a security team small enough to list by name in one sentence.

** Compromised LiteLLM 1.107.0 on PyPI installs a credential stealer and backdoor :security:supply-chain:python:pypi:llm:

:ID:       50181114
:URL:      https://safedep.io/litellm-pypi-compromise-credential-stealer-backdoor/
:HN_URL:   https://news.ycombinator.com/item?id=50181114

*** TLDR
All seven platform wheels of LiteLLM 1.107.0 on PyPI carried a credential stealer and a persistent backdoor. The stealer collected sixteen categories of secrets: SSH keys, AWS, Azure, Google Cloud and Kubernetes credentials, browser passwords and history, GitLab, Jenkins, Terraform and Vault secrets, tokens for Claude, Cursor, Copilot and Hugging Face, and the LiteLLM proxy's own database with the provider API keys in it. It encrypted the haul with AES-256-CBC under an RSA-OAEP wrapped key and sent it to a lookalike domain. The backdoor shipped as sitecustomize.py, so it started on every Python process on the machine whether or not anything imported litellm, re-ran the stealer hourly with no per-host limit, and read server addresses from an attacker GitHub repo to exec whatever it was served. The entire payload came from one added line in pyproject.toml: data = "cook". SafeDep found the source distribution diverged from its tagged commit while the wheels matched the project's real maturin build pipeline, with no public GitHub Actions run in the build window, and assesses with moderate to high confidence that the private build pipeline was modified. Upload to takedown was roughly two hours; 1.106.2 and the release candidates were clean.

*** Take
The sitecustomize.py is the part to copy into your threat model. One bad package in one virtualenv got code into every Python process on the host, so "I never imported it" is not a defense and neither is uninstalling the package. If 1.107.0 touched a machine, the machine is the blast radius, and the LiteLLM proxy database makes that worse: the stealer went looking for the one file that holds every provider key you were proxying.

*** TLDR
DuckDB 2.0.0 lands with nearly 20,000 commits since 1.5, and the team calls it their biggest feature release. The Quack protocol now backs a real client-server deployment, and a new CONNECT statement attaches to remote databases including PostgreSQL and MySQL. Asynchronous I/O for Parquet and CSV reads in parallel in the background, which mainly helps queries against remote storage. VARIANT is now a first-class type that detects and compresses semi-structured data. The legacy PostgreSQL-derived SQL parser is replaced by a PEG-based parser, so extensions can hook into the grammar itself, and organizations can host their own cryptographically verified extension repositories. New SQL: triggers, data-modifying CTEs, NEAREST joins for similarity search, nested schemas, JSON mutation functions. CLI agent mode cuts output volume 59% for AI-driven queries. Support is guaranteed through October 2027, and 1.5 also became an LTS with support to March 2027. Breaking changes: the storage format changed so pre-2.0 versions cannot read databases created by 2.0 (2.0 still reads older files), C++17 is required, and the single-arrow lambda syntax is off by default.

The client-server mode is the line people will argue about, because it moves DuckDB out of "the SQLite of analytics" and into territory where you can put a team behind one instance.
