*** TLDR
Binary Security documents five elevation-of-privilege bugs in Azure Logic Apps API Connections, the component that stores credentials for Key Vault, Azure SQL, Jira and Salesforce. Path traversal in the DynamicInvoke endpoint reached other tenants' connections; the undocumented DynamicList, BlockedList and DynamicSchema endpoints had the same flaw, including arbitrary operations on a victim's SQL database; and Consumption Logic Apps could pass an arbitrary runtimeUrl to skip the ownership check, which was then bypassed a second time because path normalization ran after validation. The author puts the root cause on ARM having full access to everything plus validation by blacklist, and reports $200,000 in bounties across the reports.

*** Take
Each fix blocked a specific string and the next request found a different route to the same over-privileged backend, which is what makes this five findings instead of one. Microsoft paid $200,000, so it knows the price of the bug class; the architecture that keeps producing it has not changed.

** Show HN: A working Nintendo in ~1GB of Qwen weights :ai:emulation:retrocomputing:showhn:

*** TLDR
Nesformer puts an NES 6502 CPU inside the weights of a stock Qwen3.5-4B. Nothing was trained: a compiler computes every weight, using each DeltaNet attention head's 128x128 state matrix as addressable memory with one-hot keys and queries, so cartridge ROM, work RAM and CPU registers live in matrix rows. Seven Gated DeltaNet layers handle the program counter, instruction fetch, decode, address calculation, memory access and result, while a host program drives the PPU, controller input and timing. It covers all 151 official opcodes plus NMI and BRK, is limited to NROM cartridges with no sound and no IRQ, and ships 466.6M parameters of which 9.3M are nonzero, 3.3MB compressed. Speed is about 1,650 tokens/s on one CPU core against the roughly 700,000 tokens/s a real NES needs, so 150 to 290 times slower than the hardware.

*** Take
The weights came out of a compiler, not gradient descent, which is the actual result here: a transformer's state matrices are being used as RAM and a register file. The same work sets the ceiling, because 150 to 290 times slower than a 1983 chip is a clean price tag on moving a deterministic circuit into a model.

Claimed results are 5x merges per engineer since January, revert rate under 0.5%, customer-facing changes up from 17 to 30 a month to 45 to 48, and 1.75x faster feature delivery with planning and review now 70% of the timeline.

*** Take
Every number measures the pipeline, not what comes out of it. The top comment asks for revenue, margin or customer satisfaction and the thread has none of them, which leaves merges per engineer doing exactly the job lines of code used to do. The 0.5% revert rate is the one figure worth keeping, and it only tells you what got caught.
