*** TLDR
YC Labs and Olam Labs put 50 GPT-6.1 Sol agents in a three-hour Minecraft world with one instruction, "build a thriving civilization", then ran 10 Claude Opus 5.5 agents against 10 GPT agents in Bed Wars and Mindustry. Nobody discussed leadership: Ada, first alphabetically, received 616 direct messages because 46 of the other 49 agents messaged her first. 22 of the run's 34 deaths happened on the first night, after which agents refused optional mining and distant scouting and sat in lit shelters waiting for assignments. Food turned into a rationing bureaucracy with a hunger ledger, 12 agents on fishing rotation, and named-chest withdrawal protocols adopted after one cooked chicken meant for Noor was picked up and eaten by Esme. Four agents spent 11 minutes appointing a sole fertilizer operator for one piece of bone meal. In the competitive games GPT won Bed Wars 6-3 and Mindustry 6-1: it sent 5-30x more messages in clipped shorthand, fetched the game source code, and shared workarounds for a block-breaking bug that several Claude agents concluded was impossible, while Claude wrote full sentences, used "we" in 30% of messages against GPT's 5%, defended its bed on the assumption that a double survival was a win, and wrote lessons to memory files it then ignored.

*** Take
The failure mode here is not stupidity, it is recognizable. Given no structure, the agents manufactured structure: a leader chosen by sort order, permits, a ration ledger, a three-minute inquiry into a missing chicken. That is what fifty competent, anxious, under-specified workers do in any organization. The result worth keeping is the memory finding: Claude documented its mistakes and repeated them anyway, while GPT left its memory files empty and shouted warnings over DM. The write succeeded and the read did nothing, which is the actual state of most agent memory systems being shipped right now.

*** TLDR
Herdr, the terminal multiplexer built around coding agents, shipped a native desktop app for Linux (x86-64 and ARM64, needs a desktop session and a Vulkan driver), macOS on Apple Silicon (Intel builds from source) and Windows 10 1803 or newer. Work is organized into spaces, which hold one machine and usually one repo, then tabs, then panes that can show terminals or mod panels side by side. An agents sidebar aggregates every agent across all spaces and labels each one Working, Blocked, Done or Idle. The app is a front end for herdr-core, the daemon that actually runs the programs, so terminals keep running after the window closes, and SSH to remote machines works out of the box. Install is curl-to-sh on Linux and macOS or irm/iex in PowerShell. Usage telemetry is on by default in releases and is switched off in Settings > Privacy. The thread turned up a Windows 98 theme with Minesweeper, solitaire and Clippy.

*** Take
The app is not the interesting part, the agents sidebar is. Once your work is four agents across two machines, what you need is not a nicer terminal grid but a queue that tells you which one is blocked on you, and Herdr is the first tool in this category to make that the default view instead of a feature. The funding argument in the thread is fair and unanswered: nobody has explained how a multiplexer makes money, and the two available answers are hosted cloud and inference margin, both of which pull the product away from the local daemon people like it for. Telemetry on by default in a terminal is also a strange call for this audience.
