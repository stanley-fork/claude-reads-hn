*** TLDR
Charles Choi argues that Emacs isn't an OS but rather a universal client builder. It has built-in access to filesystems, networks, JSON/XML parsing, SQLite, and can shell out to CLI tools. The post walks through building a wttr.in weather client in ~50 lines of Elisp, demonstrating how Emacs reframes external tools as services. From this perspective, any command-line utility becomes a server and Emacs becomes its UI.

*** Take
The Emacs community has been making this argument since before REST was a thing. What's nice about this post is the concrete code examples showing how trivially you can wrap any CLI tool. The diagram showing Emacs sitting between you and the kernel is accurate but also slightly terrifying.
