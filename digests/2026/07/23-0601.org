** git's --end-of-options Flag :git:security:package-managers:cve:
:PROPERTIES:
:ID:       48991882
:URL:      https://nesbitt.io/2026/07/21/end-of-options.html
:HN_URL:   https://news.ycombinator.com/item?id=48991882
:POINTS:   66
:COMMENTS: 25
:BY:       Erenay09
:END:

*** TLDR
Andrew Nesbitt discovered git's --end-of-options flag while reading a CVE fix. Unlike standard Unix -- which marks end of options, git already uses -- to separate revisions from pathspecs. So git needed a different marker for the revision parser, added in git 2.24.0 back in 2019. Of 19 package managers checked, only Go's cmd/go actually uses it. The article catalogs CVEs across Bundler, Composer, Poetry, pip, CocoaPods and Go that all stem from argument injection via malicious branch names starting with dashes.

*** Take
Six years of a security-critical flag hiding in plain sight while package managers kept shipping vulnerable code. The real kicker: most tools can't even use --end-of-options because they need to support git versions from LTS distros still running 2.17.0. Ubuntu 18.04 support until 2028 is actively holding back security.
