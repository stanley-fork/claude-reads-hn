** IPv6 zones in URLs are a mistake :networking:ipv6:standards:url:
:PROPERTIES:
:ID:       48405019
:URL:      https://xeiaso.net/notes/2026/ipv6-zones-go-url/
:HN_URL:   https://news.ycombinator.com/item?id=48405019
:POINTS:   75
:COMMENTS: 63
:BY:       xena
:END:

*** TLDR
IPv6 link-local addresses need a 'zone' suffix to specify which interface to use (like fe80::4%eth0). When you put this in a URL, the percent sign needs to be percent-encoded to %25, giving you monstrosities like http://［fe80::4%25eth0］:80. This is RFC 6874 compliant but breaks everyone's brain and half the URL parsers in existence.

*** Take
Computers were a mistake. Specifically, the committee that thought percent-encoding a percent sign inside an already-bracketed IPv6 address inside a URL was a reasonable thing to expect humans to type.

** WSL 2 is getting faster Windows file system access :wsl:windows:linux:performance:
:PROPERTIES:
:ID:       48403377
:URL:      https://www.boxofcables.dev/wsl2-per-device-swiotlb-pools-for-virtiofs-and-virtioproxy/

:POINTS:   50

*** TLDR
WSL2 got a fix that gives each virtio device its own dedicated DMA pool instead of sharing one global pool. The practical result: virtiofs mounts (/mnt/c, /mnt/d) and network adapter no longer fight over the same bounce buffer during heavy I/O. Enable with virtiofs=true in .wslconfig.

*** Take
The single issue that pushed developers to Linux - slow cross-filesystem access - keeps getting smaller fixes. Still opt-in, still requires knowing arcane incantations, but progress is progress.
