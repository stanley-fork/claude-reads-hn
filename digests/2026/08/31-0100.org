** Arbitrary code execution in QubesOS via copy-to-VM error reporting :security:qubes:vulnerability:linux:
:PROPERTIES:
:ID:       49496918
:URL:      https://www.qubes-os.org/news/2026/08/29/qsb-118/
:HN_URL:   https://news.ycombinator.com/item?id=49496918
:POINTS:   203
:COMMENTS: 83
:BY:       vntok

*** TLDR
QubesOS (the 'reasonably secure' OS) had a shell injection vulnerability where a malicious VM could inject arbitrary commands into dom0 via crafted filenames in qvm-copy-to-vm error messages. The sanitization function filtered non-ASCII and quotes but forgot shell metacharacters, then passed the result to system().

*** Take
The OS that exists specifically to prevent VMs from escaping had a classic shell injection bug. The 'sanitize' function did everything except actually sanitize. At least the fix is trivial: stop using system() like it's 1999.
