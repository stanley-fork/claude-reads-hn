*** TLDR
A Nix project that turns NES gameplay into derivations. Each button press becomes a separate derivation whose input is the previous frame's savestate. The attribute path IS the input sequence: `.#level1.rightb.rightb.rightab` means 'run right, run right, run-jump'. Nix's laziness means the infinite game tree is never fully evaluated. The store becomes savestate history - branching off a 100-press run costs one derivation. Limited by max-call-depth (fixable) and Linux argv limits (work around via file input).

*** Take
Someone looked at Nix's recursive attribute sets and thought 'what if the attribute path was a speedrun?' The Nix store as a savestate manager is either the most elegant abuse of a package manager or proof that Nix people will turn anything into a derivation. Both, probably.
