*** TLDR
Boris Cherny lays out the six-step loop he says he runs many times a day: understand the information you have, gather what is missing, define the problem, define a clear and simple approach, define a goal, act with urgency. His argument is that being wrong is not waste, it is the input that lets you revise steps three through five when new data arrives. He says teams break most often at step three, an unclear problem definition, and step four, an approach that is too complex, which leaves the success criteria vague. The post gives no project examples.

*** Take
The framework itself is unremarkable, which is why the thread went somewhere else entirely and started listing open Claude Code bugs. A post inviting new data gets new data. The sequencing question commenters raised is the real one: defining the goal after the approach means the approach ends up setting the bar it will be measured against.

** Why MCP Was Always a Bad Idea? :ai:mcp:agents:protocols:
:PROPERTIES:
:ID:       49779329
:URL:      https://maharship.com/blog/why-mcp-was-always-a-bad-idea/
:HN_URL:   https://news.ycombinator.com/item?id=49779329
:POINTS:   95

:BY:       maharshi365

*** TLDR
The case against MCP here is context bloat: every server ships a set of tools with schemas that fill up the model's context, and services like Composio and MintMCP hide that rather than fix it. The author argues the scaffolding built around older models' limits is now pure overhead. The proposed replacement is agents calling HTTP APIs directly with ordinary docs and auth, discovering CLI tools by running --help, and documentation sites honoring an Accept: text/markdown header so agents get markdown instead of HTML. There are no benchmarks or numbers in the post, the argument is entirely qualitative.

*** Take
The post is right that a terminal agent with unrestricted network access does not need most MCP servers, and it never asks why you might not want a terminal agent with unrestricted network access. That is exactly what the top comment supplies: MCP is about choosing which capabilities are exposed, not about making them reachable. Just give it a shell is an answer that comes with a threat model attached.

*** Comments

*** TLDR
An excerpt from Danny Bate's book Why Q Needs U on how W got into the alphabet. After Rome fell in the fifth century, Germanic rulers needed scribes to write their names in Latin script, and Latin had no letter for the /w/ sound because V had shifted to /v/.
