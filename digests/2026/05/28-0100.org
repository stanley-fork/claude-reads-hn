** Go: Support for Generic Methods :go:generics:programming-languages:type-systems:
:PROPERTIES:
:ID:       48291575

:HN_URL:   https://news.ycombinator.com/item?id=48291575

*** TLDR
Go is finally adding generic methods after years of saying 'we don't know how to implement them.' The key insight: methods are useful for code organization and chaining (x.a().b().c()) even without interfaces. Generic methods won't satisfy interface methods since interfaces can't have type parameters, but that's fine. Spec change is minimal, implementation uses existing stenciling approach.

*** Take
The FAQ literally said 'we do not anticipate that Go will ever add generic methods.' Five years later, turns out they just needed to decouple methods from interfaces conceptually. Someone in the comments is already threatening to build a monad library. We were warned.
